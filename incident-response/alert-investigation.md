# Wazuh Alert Investigation and Incident Response

## Overview

This document describes the basic SOC alert investigation workflow used in my Wazuh-based home lab.

The objective is to review security alerts, identify suspicious activity, correlate endpoint telemetry, and determine whether an event represents a real security incident.

---

## Alert Investigation Workflow

When a security alert is generated in Wazuh, the investigation process follows these steps:

1. Review the alert severity.
2. Identify the affected endpoint.
3. Identify the user associated with the activity.
4. Review the event timestamp.
5. Analyze the rule that triggered the alert.
6. Examine the process and command-line information.
7. Check related Sysmon events.
8. Review Windows Security Event Logs.
9. Search for related alerts around the same time.
10. Map the activity to MITRE ATT&CK.
11. Determine whether the activity is legitimate or suspicious.
12. Document the investigation findings.

---

## Important Information Reviewed

During an investigation, the following information may be examined:

- Source IP address
- Destination IP address
- Hostname
- Username
- Process name
- Parent process
- Command-line arguments
- Event ID
- Rule ID
- Alert severity
- File path
- File hash
- Network connections
- Related security events

---

## Example Investigation: Suspicious PowerShell Activity

A suspicious PowerShell alert can be investigated by reviewing:

- Which user executed PowerShell
- Which process launched PowerShell
- PowerShell command-line arguments
- Execution time
- Related Sysmon events
- Network connections generated by the process
- Other alerts generated from the same endpoint
