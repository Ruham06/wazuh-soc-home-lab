# Wazuh Threat Hunting

## Overview

Threat hunting is a proactive process of searching for suspicious or malicious activities that may not have triggered traditional security alerts.

In this Wazuh SOC Home Lab, threat hunting was performed using Windows telemetry, Sysmon logs, PowerShell events, Windows Defender alerts, and Wazuh security events.

## Data Sources

The following data sources were used during threat hunting:

- Windows Security Event Logs
- Sysmon Events
- PowerShell Logs
- Windows Defender Logs
- Wazuh Alerts
- File Integrity Monitoring Events

## Threat Hunting Process

The basic threat hunting workflow used in this lab was:

1. Identify suspicious activity.
2. Search related events in Wazuh.
3. Analyze the source host and user.
4. Review process execution information.
5. Check parent and child processes.
6. Review network activity if available.
7. Correlate events with Sysmon telemetry.
8. Map suspicious behavior to MITRE ATT&CK.
9. Determine whether the activity is malicious or legitimate.

## Example Threat Hunt

One example threat hunting scenario involved reviewing suspicious PowerShell activity.

The investigation focused on:

- PowerShell process execution
- Command-line arguments
- User account involved
- Parent process
- Related Sysmon events
- Network connections
- Security alerts generated by Wazuh

This helped determine whether the PowerShell activity was normal administrative activity or potentially malicious behavior.

## MITRE ATT&CK Mapping

Threat hunting activities can be mapped to MITRE ATT&CK techniques such as:

- T1059 - Command and Scripting Interpreter
- T1059.001 - PowerShell
- T1055 - Process Injection
- T1105 - Ingress Tool Transfer
- T1071 - Application Layer Protocol
- T1082 - System Information Discovery
